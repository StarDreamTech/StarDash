# 星盘 StarDash：电脑状态与快捷操作需求整理

整理日期：2026-11-17。依据本机星匣档案中的原始对话及本次补充需求。

## 当前实现进度（2026-11-17）

用户随后要求“继续实现”，现已完成 **0.2.0 本地体验版**：CPU、内存、实时上传／下载、电池／供电，菜单栏面板与悬浮窗口切换，精简／展开、置顶、显示项目选择、设置和窗口位置保存，以及定时防休眠。防休眠提供 15／30／60／120 分钟，精简窗口保留活动倒计时和结束按钮。

新增用户明确提出的命令快捷图标：输入命令、设置名称和图标，保存后成为可点击图标，点击打开系统终端执行；支持右键编辑、确认删除及重启恢复，两种面板形态共用，精简模式也保留。命令使用登录、交互式 zsh，默认从用户主目录开始，支持 `cd`、中文、引号、管道及多行；保存或恢复时不自动执行。命令自检及本机真实终端执行已通过。

release 构建、本地临时签名、16 项自检及实际系统防休眠超时测试已通过。悬浮窗口操作和重启恢复已实测；菜单栏面板已核对显示，面板内控件的自动化逐项操作仍受验证工具绑定限制。详细证据与未验证范围见 [验证记录](verification.md)。

本版仅在 Apple Silicon、macOS 27.2.1 验证，尚未公证。图标收纳、自动更新、全局快捷键及下文标注的后续项目仍未实现；历史原型未运行。

以下章节保留需求来源及规划，表内“建议”表示来源性质，不代替本节的实现状态。

## 1. 产品定位与需求依据

星盘是一个 Mac 小控制中心：集中查看电脑状态、使用常用快捷操作，并保留菜单栏图标收纳这一产品方向。界面可以是从菜单栏展开的小面板，也可以是小悬浮窗口。

本文区分三种依据：

- **用户已确认**：用户在原始对话或本次对话中明确提出的要求。
- **历史建议**：以前的 AI 提出的功能细项，未发现用户逐项确认。
- **本轮建议**：为形成可开发清单而补充的内容与优先级，仍可调整。

| 事项 | 原始依据 | 结论 |
| --- | --- | --- |
| 三个功能方向 | 2026-11-05，用户回答“收纳图标，再加电脑状态和快捷开关” | 用户已确认 |
| Mac 专用 | 2026-11-05，用户明确“不用考虑兼容多端” | 按 Mac 专用开发；仓库 README 已统一 |
| 图标收纳的正确交互 | 2026-11-05，用户纠正：在收纳盒里的图标旁出现原来的操作菜单 | 用户已确认；只让顶部图标响应不符合要求 |
| 一键更新 | 2026-11-05，用户询问本产品是否也能支持一键更新 | 保留为产品配套需求，尚不能当作已接入 |
| 展开面板或小悬浮窗口 | 本次对话，用户明确提出两种形态 | 两种形态均保留；建议共用内容与设置 |

历史中的 CPU、内存、网速、电池及定时防休眠，均有明确的建议记录；这些具体项目应区别于用户已经确认的三个方向。历史建议按本次用户调整后的范围取舍。

## 2. 需要展示的电脑状态

以下“首版”来自本轮范围建议；当前实际完成内容见开头进度，其中“展开后的补充信息”尚未实现。

| 类别 | 建议首版显示 | 展开后的补充信息 | 依据与优先级 |
| --- | --- | --- | --- |
| CPU：处理器负载 | 当前总使用率 | 近期变化；查看活动监视器入口 | 历史建议；首版 |
| 内存 | 已用量、总量和使用比例 | 内存压力，即系统内存是否吃紧 | 历史建议类别；显示细项为本轮建议；首版 |
| 网速 | 当前上传速度、下载速度，方向和单位明确 | 当前网络连接、累计流量 | 历史建议类别；显示细项为本轮建议；首版先做实时速度 |
| 电池与供电 | 剩余百分比、充电／使用电池／已接电状态 | 电池健康等详细信息 | 历史建议类别；显示细项为本轮建议；首版做电量与供电 |
| 磁盘空间 | 可用空间、总容量 | 各磁盘使用情况 | 本轮补充；首版之后 |
| 当前网络 | 已连接／未连接、连接类型 | 网络名称、IP 等按需展开 | 本轮补充；首版之后 |
| 温度、风扇、GPU | 暂不列为首版必做 | 先核实设备覆盖、数据取得方式和常驻成本 | 本轮候选；尚未验证 |

显示约定建议：

- 默认先呈现 CPU、内存、上传／下载、电池四组核心信息，详细数据按需展开。
- 无电池的电脑不显示电池卡；不能取得的数据显示“不可用”及原因，不以 0 代替。
- 状态以数值和文字为主，颜色辅助；图表和装饰动画不是首版前提。
- 防休眠是否开启及剩余时间，要直接反映在相应操作控件中。
- 当前展示时每 2 秒采样、隐藏时每 10 秒采样；尚未做长期耗电及常驻占用专项验证，不预设性能指标。

## 3. 需要提供的快捷操作

用户已明确排除音量调节／静音、音频设备查看／切换、锁屏，使用 macOS 已有功能；星盘不再重复提供这三项。

| 操作 | 建议首版行为 | 依据与优先级 |
| --- | --- | --- |
| 定时防休眠 | 开启／关闭；选择持续时间；显示剩余时间和当前状态 | 历史建议；首版已实现 15／30／60／120 分钟 |
| 命令快捷图标 | 输入指令并保存为可点击图标，点击打开终端执行；可命名、选图标、编辑和删除 | 本次用户明确新增；0.2.0 已实现 |
| 形态切换 | 将临时展开面板切换为常驻小窗口，或回到菜单栏面板 | 两种形态来自本次需求；切换方式为本轮建议 |
| 快速打开系统页面 | 活动监视器、网络设置等入口 | 本轮补充；首版之后 |
| 亮度等显示控制 | 调节受支持屏幕的亮度等 | 本轮候选；设备覆盖尚未验证 |
| Wi-Fi／蓝牙／专注模式 | 先明确需要直接开关、设备选择还是设置入口 | 本轮候选；接口与权限未验证，不纳入首版承诺 |

普通操作需要就地反馈：切换后的状态、执行中的提示以及失败原因。当前防休眠使用系统限时空闲睡眠断言，允许屏幕熄灭，不改变合盖或手动睡眠；“保持唤醒”和“合盖继续运行”不能当作同一个已完成的功能。

## 4. 两种展示形态

建议使用同一套状态数据、操作和用户配置，只改变打开方式与常驻行为。

| 形态 | 使用方式 | 适合放什么 |
| --- | --- | --- |
| 菜单栏展开面板 | 当前点击菜单栏入口呼出；默认临时查看和操作，快捷键后续再做 | 完整的核心状态、快捷操作，未来可增加图标收纳区域 |
| 小悬浮窗口 | 保留在桌面，能拖动位置；建议支持精简／展开及置顶开关 | 用户选择的少量状态，点击展开常用操作 |

建议的展开面板顺序：

1. 顶部：星盘入口、切换为悬浮窗口、设置。
2. 状态区：CPU、内存、上传／下载、电池。
3. 操作区：定时防休眠开关、持续时间与剩余时间，命令快捷图标。
4. 图标收纳区：后续在真实菜单交互验证后加入。

悬浮窗口支持精简，不必长期展开所有操作。当前默认展开，随后记住用户选择；允许用户决定显示哪些状态，并记住位置和显示方式。已核对本机拖动、置顶和重启恢复，多屏、全屏应用与窗口焦点边界仍待专项验证。两种形态共用同一数据与操作状态。

当前实现内容宽度为 372pt、系统材质背景，默认菜单栏面板、展开且不置顶，后续恢复用户设置。吸边、透明度调节和全局快捷键未实现；这些实现选择仍可按体验调整。

## 5. 图标收纳：保留需求，单独验证

用户要的完整行为是：

- 将顶部应用图标收纳进小面板；后续也讨论过由用户手动隐藏、再选择加入的替代流程。
- 在收纳盒里点击或右键图标，在该图标旁弹出原有操作菜单，并执行其中操作。
- 能恢复或移出收纳，不影响原应用正常使用。

2026-11-05 的原型记录显示：手动添加、图标展示和收藏保存已有实现记录；隐藏后调用真实原菜单未跑通，转发顶部点击也不符合用户纠正后的需求。历史还记录了顶部菜单栏无响应、退出原型后仍异常、重启恢复，具体原因未查明。

以上为历史状态，本轮未运行原型、未重测菜单操作或修改系统设置。因此，图标收纳仍应作为待验证模块，不能写成星盘现有可用功能。

建议状态与快捷操作先形成可用版本；收纳模块独立验证“隐藏后可操作、菜单在盒内图标旁出现、恢复正常、无焦点干扰”，通过后再接入主面板。

## 6. 建议的第一版范围

**当前版：**菜单栏展开面板＋小悬浮窗口；CPU、内存、实时上传／下载、电池／供电；定时防休眠；命令快捷图标；基础显示选择与设置保存。

**后续：**磁盘空间、网络详情、趋势图、更多系统操作、图标收纳。温度／风扇／GPU及直接控制无线开关等，在技术验证后决定是否进入范围。

AI 用量、视频下载等虽在历史竞品介绍中出现，但未找到用户将它们确定为星盘需求的记录，未自动纳入本清单。

一键更新保留为配套需求；更新源、校验、安装与失败恢复需要单独落实，当前不计为已完成能力。
